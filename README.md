# 心理史学 · 谢顿计划

30 回合的合成银河策略游戏。你接过谢顿计划，续写历代执掌者的工作，在帝国衰落中回应急电、照看星区，把知识送往基地。纯前端运行，没有后端、账号或外部 AI API。

[在线体验](https://psychohistory.help/)

## 本地运行

```powershell
npm ci
npm run dev
```

打开终端显示的本地地址，默认 `http://127.0.0.1:5173`。设置种子与星区规模后，可完成或跳过三步入门。新版正式游戏每回合：可选地准备一张命令卡并指定目标 → 阅读急电并选择回应 → 自动推进十年 → 阅读约 1000 字的十年手记。没有急电时点击「渡过十年」。共 30 回合、300 年，分为衰落、裂变、保留知识三个阶段。

八类急电包括粮运、总督抗命、知识转移、自治请愿、融资、教育争执、难民与幕后协调。出现时机、类别与目标会随种子和局势变化；选择会改变实际资源和状态，谈判与融资含成功、失败分支。事件和卡牌共享影响力与国库。选项不直接展示数值收益、成功率或后续剧透；不足以同时支付事件与准备命令的选项不能执行。

十年手记依据已经执行的事件、命令和真实模拟结果在本地构建，区分事件成功与失败、恢复与失守、财政与知识保存。它不调用外部 AI，也不预测尚未发生的历史。顶部「十年手记」可翻看已完成的卷次，阅读中刷新可继续；具体条件、概率和机制留在星图档案里。

新版包含 13 种卡牌，每回合抽取 5 张干预牌加固定等待牌。新增紧急粮运、护航航线、星际商贸、边疆调停、第二基地情报网、档案撤离。主交互与十年手记以文字为主，不展示封面或卡牌大图；卡牌图鉴默认也为文字，只在主动点击图片按钮时展开一张插画。图鉴可按知识、政治、物流、贸易、情报、信念、等待筛选；不在当前手牌中的牌不能执行。可选插画资源与生成提示见 `assets/card-art.json`。

新模型增加补给、贸易、情报、自治、干预疲劳五组状态。局部干预按航线距离、补给、贸易和中转局势作有界的两跳传导，独立星区不能中转。补给在邻区间同步交换，贸易支撑生产与税收，情报削弱风险与共同冲击暴露，自治以税收让步降低分离风险，重复的新卡干预有递减收益。事件的随机成功率以当前合法性、治理、派系、情报、贸易和危机修正对数胜算。所有数值仍是合成游戏参数，不声称提升现实社会预测能力。

`strategic`、`atlas` 为新推演的可选协议标记。旧存档继续使用旧手牌、世界坐标、事件规则和原模型指纹；旧整局回归快照保持不变。新版依然每步消耗固定的 `5 + 9N` 个现实随机数，叙事与地图探索不消耗现实随机流。

新推演加入 12 个原著主线章节：谢顿审判、四王国制衡、维恩尼斯危机、阿斯康禁令、马洛受审、科瑞尔贸易战、里奥斯进攻、帝国召回、川陀图书馆、第二基地搜寻、阿卡蒂航线与帕尔弗的制度选择。外交承诺、贸易网络、保密度由实际选择积累，影响后续成功率、恢复收益和叙事结局。例如公开马洛的记录提高贸易网络但降低保密；保存前线产业会提高撤军后的恢复收益。可回看已完成章节与所选回应，终局报告也包含这些记录。

启用骡时，冲击在帝国反攻后的随机回合发生，解锁穹窿错位、贝泰保护线索与罗瑟姆诱饵三个响应章节；只有已经观察到冲击才显示相关剧情。预测器仍排除未观察的骡冲击，不读取它的出现回合。主线按可见章节顺序推进；被响应事件推迟的章节会补发，每章只结算一次。无资源时仍有免费选项，失守星区不会被剧情复活。

「原著档案」整理基地 7 卷、帝国 3 卷，以及《我，机器人》短篇集与 4 部机器人长篇，提供核对链接和阅读路线。本局主要改编基地前三部；后传与机器人作品提供背景阅读，不将更晚时代直接塞进 300 年推演。原著线索用新文案概括，选择、概率、年代和制度效果是游戏改编；游戏纪元不是逐章原著年表。既有存档维持原有事件规则与模型指纹，开始新推演才启用相互影响的主线。

书目核对：[Penguin Random House 基地系列](https://www.penguinrandomhouse.com/series/FOU/foundation/)、[机器人书目](https://www.penguinrandomhouseretail.com/book/?isbn=9798217093472)、[帝国三部曲馆藏](https://books.google.com/books/about/Triangle.html?id=iNc2AAAAIAAJ)。情节交叉核对：[《基地》](<https://en.wikipedia.org/wiki/Foundation_(Asimov_novel)>)、[《基地与帝国》](https://en.wikipedia.org/wiki/Foundation_and_Empire)、[《第二基地》](https://en.wikipedia.org/wiki/Second_Foundation)。情节条目含剧透；事件旁的说明区默认折叠。

顶部“大数定律”可查看统计对照。每回合和待执行的事件回应都会自动保存在当前浏览器；刷新可继续，结局也可恢复。新推演会替换当前存档。结束后可导出 JSON 报告，包含种子、参数、事件回应、卡牌、历史与模型指纹。

新推演默认使用用户提供的银河帝国行政地图照片，并可切换到全息星图。照片原文件保留在 `public/maps/`，界面通过裁切视窗叠加动态星区、航线与状态，不重绘原图文字。30、50、80 个可玩节点是依据照片重建的近似游戏锚点，不是精确星位或完整地名转录。发布该参考照片前需确认图片及地图的使用授权。

行政图支持拖动平移、滚轮与双指缩放、缩放/复位按钮、键盘操作；全息图保留旋转、缩放与右键平移。可切换风险、补给、贸易图层，并搜索或点击星区。档案包含当前条件、战略状态、概率分叉、风险贡献、急电与实际历史，显示避开独立星区并考虑距离、危机和补给的川陀航线，邻区按钮可继续探索。

底部银河纪元滑块可回看已经发生的回合，也可连续播放。历史状态从种子与实际行动在独立随机流中重放，不改变当前局势、行动或存档；历史视图中的单步概率将共同冲击设为零，与实时蒙特卡洛预测分开标注。返回当前后，历史中查看的星球须明确选为干预目标才会改变命令。人口信息使用模型权重，不虚构绝对人口或原著危机日期。

首次打开页面即播放约 3.2 秒星河聚合与镜头推进，按钮或 Escape 可跳过；之后自动省略。开局页和桌面顶部均可重看，点击开始推演不会再次播放。减少动态效果设置会跳过首次动画并停止旋转与脉冲运动。星尘使用批量粒子渲染、标签使用 HTML；小屏与持续低帧率会降低粒子数量和分辨率，并关闭 Bloom。WebGL 无法使用或丢失上下文时保留可交互的平面星图。手机上的星区档案位于星图下方，可独立滚动。

星河结合暖色核心与蓝紫星云；星云贴图一次生成、单次绘制。银河事件流默认收起，可按危机、恢复/知识、政治筛选，或搜索星区、事件与人物。原著主线的记录同时显示书名与相关人物；点击记录会定位到对应星球与历史回合，保持当前推演存档不变，未发生的结果不进入事件流。手机事件流和星区档案位于地图下方，不拉伸或遮挡照片。「沉浸星图」可切换全屏，保留事件流、星区档案和纪元滑块。

```powershell
npm test -- --maxWorkers=1
npm run format:check
npm run build
npm run sim -- --policy=all --games=100 --seed-prefix=v3-final-heldout
npm run study:cards
npm run validate:model
```

同一种子、参数和同一行动序列可复现世界、手牌、急电与现实路径。预测、现实与校准随机流分离；所有分支保持现实抽样预算相同。生产构建在 `dist`；`npm run preview` 可预览。图表在本地渲染，不需网络资源。

成绩使用 `F_eff = 0.1 + 0.9F`、`Q = √(F_eff × S)`，S 为最后三回合平均稳定占比。维稳有基础分，基地收益递减并依赖稳定与端点星；满进度后仍可提供知识援助。减税仅持续四回合，精英安置影响邻区，影响力通常每回合恢复一点。

预测按当前事件回应与卡牌执行，之后按兵不动、暂缓后续事件。未来急电通过独立流采样；预测器不读取现实未来的事件日历，也不知道可选的“骡”。“骡”在随机回合出现，可能击穿事前预测区间。手牌推荐在后台用 32 条配对路径粗估，选中后用 96 条精算；结果在星图档案中按需展开。目标热力图是共同冲击为零的单步示范，定向候选经过筛选，均不构成最优保证。自动推进只接受与当前回合、事件回应、命令和参数匹配的预测，避免误用上一次预览。

PITF 和结构人口理论仅提供定性启发；数值是游戏参数，不是实证系数。独立对照关闭邻区传染、共同冲击、财政反馈与跨区事件；新版还关闭战略反馈与邻区补给交换，避免运输关系继续耦合各星区。合成校准不证明现实社会的预测能力，单局覆盖率也不足以检验校准。自动完整游玩验证与人类体验评价不同，目前没有“真人十分钟一局”的实测结论。

## 网站部署

GitHub Pages 使用 `.github/workflows/deploy.yml` 自动部署。向 `main` 推送后，工作流安装锁定版本的依赖、检查格式、运行引擎与事件回归测试、构建并发布 `dist`。构建从 Pages 读取子目录路径，星图、图表与预测 Worker 使用同一资源前缀。GitHub Desktop 可直接提交并推送本项目。

原始计划 PDF、本机截图、浏览器记录、验收数据、部署凭据与临时文件均保留在本机，不进入公开仓库。完整本地审阅和验收记录位于 `docs/` 与 `reports/`；批量模拟和模型验证会在本地产生 `reports/`。
